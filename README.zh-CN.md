# Visual Token Editorial

[English](README.md) · **简体中文**

这是一个 Codex 技能：它会把一张照片转化为一幅克制的编辑式视觉诗歌。原图中的真实局部被裁切出来，作为具有语义的“图像词元”嵌入句子；下方照片中的对应位置则成为精确、安静的留白。

调用名称为 `visual-token-editorial`。

## 视觉方向

每幅作品都被编排为一张竖版编辑页面：上方保留大面积暖灰白空间，下方呈现原始照片。它具有以下特征：

- 根据画面选择 4–7 个紧凑、可辨识的照片局部
- 将图像局部直接嵌入句子，让它们承担词语的语义功能
- 每幅作品只使用一种半角代码式符号：`()` 或 `{}`
- 中性无衬线字体与更紧凑的行距
- 上方文字、符号和图像词元组成的整体框架在白色区域中居中
- 下方照片的留白与上方词元使用完全一致的裁切坐标
- 保留原始矩形裁切，不使用圆角、卡片、描边、阴影或 UI 风格装饰
- 呈现安静、现代的编辑设计气质，而不是广告或拼贴簿式布局

它的核心关系是：

```text
提取 → 引用 → 移除
```

被裁下的图片不是装饰。它在句子中承担意义，同时指向自己在原照片中的准确来源。

## 生成前确认

正式处理图片之前，技能会先确认三个选项，并且只询问用户尚未说明的内容：

1. 是否需要裁剪原图
2. 文案由用户提供还是自动生成
3. 文案使用什么语言

如果原图过长或原始构图会导致成品比例过于狭长、视觉重心较弱，技能会先建议一种具体的横构图裁剪方案，并说明它会保留哪些主体内容。只有得到同意后才会裁剪。原图保持不变，另行生成一张确定性的工作裁剪图；裁剪构图锁定后，才开始生成文案和选择图像词元。后续词元坐标、遮罩、缩放及像素 QA 均以工作裁剪图为基准。

## 工作方式

这个技能支持两种文案模式：

1. **用户提供文案**：保留原文的措辞、标点、顺序和语言，再根据其中的具体名词、视觉意象或短语选择 4–7 个对应的照片局部。
2. **自动生成文案**：默认生成克制、诗意的英文文案；如果用户明确指定其他语言，则使用指定语言生成。

最终成品使用 Pillow 确定性渲染。下方图片只允许进行 EXIF 方向校正、等比例缩放和声明过的纯色矩形遮罩，不使用生成式补图、修复、重绘、调色或对象移除。


## 使用方法

上传一张照片并调用技能：

```text
使用 $visual-token-editorial，把这张照片制作成编辑式视觉诗歌海报。
```

如果希望画面围绕指定句子展开，可以直接提供文案：

```text
使用 $visual-token-editorial，并采用下面的文案：
“最后一束光越过窗户，街道仍在继续向前。”
```

也可以不提供文案，只指定语言：

```text
使用 $visual-token-editorial，这次文案使用中文。
```

对于过长的原图，可以要求技能先提出构图建议：

```text
使用 $visual-token-editorial。如果图片过长，请先建议合适的横构图裁剪方案；文案自动生成，使用意大利语。
```

## 输出

每次完成制作后，技能会返回：

1. `final.png`：确定性渲染的最终海报
2. `composition.yaml`：记录文案、排版、词元和归一化裁切坐标的可编辑源文件
3. `qa_report.md`：像素完整性与对齐检查报告

QA 报告会验证：

- 上方词元与下方遮罩的 bbox 完全一致
- 遮罩之外被修改的像素数为 0
- 遮罩内部为纯色
- 整幅作品只使用一种符号
- 符号与正文处于同一基线
- 图像词元与符号可见中线的误差不超过 1 px
- 上方完整框架的水平和垂直居中误差不超过 1 px

## 运行要求

- Python 3.10 或更高版本
- Pillow

`composition.yaml` 使用与 JSON 兼容的 YAML 写法，因此不依赖 PyYAML。
